# code/ATMOSPHERICS/

The **live and only** atmospherics engine: LINDA, vendored from /tg/ and adapted
to DeepQuarry. The old CHOMP/ZAS/XGM engine is gone, and there is no
`USE_LINDA_ATMOS` gate — this code compiles and runs unconditionally.

Gas math currently runs in **pure DM** (the `/datum/gas_mixture` proc bodies in
`gasmixtures/gas_mixture.dm`). The optional Rust-accelerated **auxmos** backend is
vendored in `verdigris/` but **not wired**: `auxmos_bindings.dm` is not compiled
and `auxtools_atmos_init()` (in `auxmos_init_bridge.dm`) is not called. Wiring it
is a future performance project — see "auxmos backend" below.

## Layout

| Path | Purpose |
|---|---|
| `gasmixtures/` | `/datum/gas_mixture`, the `/datum/gas/*` registry (`gas_types.dm`), and the gas `reactions.dm` (the CHOMP reaction roster ported onto LINDA). |
| `environmental/` | `SSair`'s turf model — `LINDA_system.dm` (adjacency), `LINDA_turf_tile.dm`, `LINDA_fire.dm`. |
| `pipes/`, `components/` | Pipenets and atmos machinery (pumps, vents, scrubbers, filters, mixers, valves, …). |
| `SSair.dm` | The air subsystem controller. Builds turf adjacency at init, processes active turfs, and (re)builds the multi-z vertical-adjacency table via `build_multiz_atmos_levels()`. |
| `xgm_compat.dm`, `tg_infra_compat.dm` | **Load-bearing** forwarding shims that expose the old XGM/CHOMP signatures (`assume_gas`, `update_nearby_tiles`, `CanZASPass`, `add_thermal_energy`, …) on top of LINDA for the ~67 consumer call-sites that haven't been migrated to native LINDA APIs yet. |
| `auxmos_bindings.dm`, `auxmos_init_bridge.dm` | The (currently uncompiled) DM side of the Rust auxmos backend. |

## Multi-z atmos

Vertical atmos adjacency is wired at init by `SSair.build_multiz_atmos_levels()`,
which bridges the movement-multiz connectivity (`GLOB.z_levels`, populated by
`/obj/effect/landmark/map_data`) into `SSmapping.multiz_levels` — the table
`init_immediate_calculate_adjacent_turfs` reads to decide UP/DOWN turf adjacency.
It is re-run when z-levels are added at runtime (e.g. `SSquarry` dig-down layers).
Whether gas actually flows vertically then follows turf density: sealed rock
blocks it, an open shaft passes it.

## auxmos backend (not wired — future perf work)

`auxmos_bindings.dm` is the autogenerated DM dispatch table for the auxmos Rust
binds: each `#[byondapi::bind("/path/in/dm")]` in the vendored auxmos forwards to
`call_ext(VERDIGRIS, "byond:funcname_ffi")(args)`. To actually run gas math in
Rust, the binding file must be compiled into the build and `SSair.Initialize()`
must call `auxtools_atmos_init()` to hand the gas registry to the arena. Until
then the binds are inert and DM does all gas math.

Regenerate the bindings (only relevant once the backend is wired) with:

```bash
bash tools/verdigris/generate_atmos_bindings.sh
```

It runs auxmos's `generate_binds` test, strips auxmos's library-detection block,
rewrites `call_ext(AUXMOS, …)` → `call_ext(VERDIGRIS, …)`, and prepends a DQ header.
