# code/ATMOSPHERICS/

The **live and only** atmospherics engine: LINDA, vendored from /tg/ and adapted
to DeepQuarry. The old CHOMP/ZAS/XGM engine is gone, and there is no
`USE_LINDA_ATMOS` gate — this code compiles and runs unconditionally.

Gas math runs in **Rust**, via the vendored **auxmos** backend in `verdigris/`.
`auxmos_bindings.dm` is compiled unconditionally and provides the `/datum/gas_mixture`
proc bodies (moles, temperature, merge, share, react, …); `/datum/gas_mixture` is a
handle into a Rust-side gas arena, not a DM data holder. Turf processing is Rust too:
`SSair.fire()` dispatches diffusion, excited groups, and katmos pressure-equalization
to the Rust engine. See "auxmos backend" below.

## Layout

| Path | Purpose |
|---|---|
| `gasmixtures/` | `/datum/gas_mixture`, the `/datum/gas/*` registry (`gas_types.dm`), and the gas `reactions.dm` (the CHOMP reaction roster ported onto LINDA). |
| `environmental/` | `SSair`'s turf model — `LINDA_system.dm` (adjacency), `LINDA_turf_tile.dm`, `LINDA_fire.dm`. |
| `pipes/`, `components/` | Pipenets and atmos machinery (pumps, vents, scrubbers, filters, mixers, valves, …). |
| `SSair.dm` | The air subsystem controller. Builds turf adjacency at init, processes active turfs, and (re)builds the multi-z vertical-adjacency table via `build_multiz_atmos_levels()`. |
| `xgm_compat.dm`, `tg_infra_compat.dm` | **Load-bearing** forwarding shims that expose the old XGM/CHOMP signatures (`assume_gas`, `update_nearby_tiles`, `CanZASPass`, `add_thermal_energy`, …) on top of LINDA for the ~67 consumer call-sites that haven't been migrated to native LINDA APIs yet. |
| `auxmos_bindings.dm`, `auxmos_init_bridge.dm` | The compiled, live DM side of the Rust auxmos backend — `auxmos_bindings.dm` provides the gas_mixture/turf proc bodies, `auxmos_init_bridge.dm` registers gas singletons + reaction tables with Rust at `SSair` init. |

## Multi-z atmos

Vertical atmos adjacency is wired at init by `SSair.build_multiz_atmos_levels()`,
which bridges the movement-multiz connectivity (`GLOB.z_levels`, populated by
`/obj/effect/landmark/map_data`) into `SSmapping.multiz_levels` — the table
`init_immediate_calculate_adjacent_turfs` reads to decide UP/DOWN turf adjacency.
It is re-run when z-levels are added at runtime (e.g. `SSquarry` dig-down layers).
Whether gas actually flows vertically then follows turf density: sealed rock
blocks it, an open shaft passes it.

## auxmos backend (wired and live)

`auxmos_bindings.dm` is the autogenerated DM dispatch table for the auxmos Rust
binds: each `#[byondapi::bind("/path/in/dm")]` in the vendored auxmos forwards to
`call_ext(VERDIGRIS, "byond:funcname_ffi")(args)`. The Rust side ships fully built —
`verdigris.dll` exports all ~112 auxmos `*_ffi` symbols (auxmos is compiled in with
the `katmos`/`katmos_slow_decompression` features) — and the DM side is compiled
unconditionally, so gas math and turf processing run in Rust with no build flag.

Key points of the live wiring:

1. **DM proc bodies are replaced, not shadowed.** byondapi is pull-based
   (`call_ext`), not auxtools-style detour hooking, so `gas_mixture.dm`'s old pure-DM
   proc bodies were removed — `auxmos_bindings.dm` is the sole definition of those
   procs, avoiding a duplicate-definition error.
2. **Rust-side gas arena.** Each `/datum/gas_mixture` is a handle carrying an arena
   index; the actual gas data lives in Rust. Code that used to touch a DM `gases`
   assoc list directly (the `xgm_compat` layer, ported `reactions.dm`) now goes
   through the handle-based proc surface instead.
3. **Gas registration and reactions.** `auxtools_atmos_init()` / `auxmos_register_gases()`
   (in `auxmos_init_bridge.dm`) register `/datum/gas` singletons and the reaction
   table with Rust at `/world/New()` and `SSair` init, before any handle proc fires.
   auxmos's `reaction_hooks` feature is disabled — reactions still dispatch back into
   DM `react()` (the CHOMP roster in `gasmixtures/reactions.dm`), so only gas-flow
   plumbing (moles, temperature, merge, share, turf diffusion, katmos equalization)
   runs in Rust.

What's still genuinely open, not blocking correctness:

- **Superconductivity** stays DM-side (auxmos's `superconductivity` feature isn't
  enabled).
- **Boot-registration overhead** — registering all gas singletons/reactions at boot
  is unoptimized; a perf pass here is a future item.

Regenerate the bindings (needed after changing the vendored auxmos surface, e.g.
adding a new bind) with:

```bash
bash tools/verdigris/generate_atmos_bindings.sh
```

It runs auxmos's `generate_binds` test, strips auxmos's library-detection block,
rewrites `call_ext(AUXMOS, …)` → `call_ext(VERDIGRIS, …)`, and prepends a DQ header.
