# modular_dq/code/atmospherics/

Scaffold for the LINDA atmospherics migration. Gated behind `USE_LINDA_ATMOS`
(see `modular_dq/code/__defines/atmospherics.dm`). **Not enabled by default**
and currently incomplete — see `modular_dq/doc/atmos_migration.md` for the
phased plan.

## Files

| File | Purpose |
|---|---|
| `auxmos_bindings.dm` | **Autogenerated.** DM-side dispatch table for the auxmos Rust binds — every `#[byondapi::bind("/path/in/dm")]` in `verdigris/atmos/src/*.rs` gets a DM proc here that forwards to `call_ext(VERDIGRIS, "byond:funcname_ffi")(args)`. Regenerate with `bash tools/verdigris/generate_atmos_bindings.sh` after any auxmos vendor bump. |

## What's missing (Phase 1.2b+)

To make `USE_LINDA_ATMOS` actually compile and run, we still need to vendor:

- `/tg/`'s `code/modules/atmospherics/gasmixtures/gas_mixture.dm` (DM-side
  `/datum/gas_mixture` skeleton — provides the procs auxmos overrides at boot,
  plus the procs auxmos does NOT override that LINDA still needs).
- `/tg/`'s `gas_types.dm` (the `/datum/gas/*` registry that auxmos consumes).
- `/tg/`'s atmos defines (`code/__DEFINES/atmospherics/*`).
- `/tg/`'s `SSair` controller and its initialization hook into auxmos.
- `/tg/`'s pipenet code.
- `/tg/`'s atmos machinery (vents, scrubbers, canisters, atmos console).
- TGUI for the above.

This is several thousand lines of DM. Each chunk should be its own PR, gated
under `#ifdef USE_LINDA_ATMOS` until Phase 4 retires CHOMP/ZAS.

## Decisions (recap from migration roadmap)

- **Library**: one combined `libverdigris.so` / `verdigris.dll` (Q4).
  `auxmos_bindings.dm` routes through `VERDIGRIS`, not a separate `AUXMOS`.
- **Features**: `katmos` + `katmos_slow_decompression` (Q1, Q5).
- **Reactions**: stay on CHOMP/XGM, not /tg/'s roster (Q6). Reaction-hook
  binds in `auxmos_bindings.dm` will be unused; auxmos's reaction module is
  compiled in but no calls reach it.
- **CHOMP atmos engine machinery**: removed (Q7). Features (lingering fires,
  phoron medical exposure) re-implemented atop LINDA later.

## Regenerating `auxmos_bindings.dm`

```bash
bash tools/verdigris/generate_atmos_bindings.sh
```

The script invokes `cargo test --package auxmos --features katmos,katmos_slow_decompression -- generate_binds`, then post-processes the output:

1. Strips auxmos's library-detection block (`__detect_auxmos`, `AUXMOS` macro).
2. Rewrites `call_ext(AUXMOS, ...)` → `call_ext(VERDIGRIS, ...)`.
3. Prepends a DQ-specific header.

The result is checked in (so DM-only contributors don't need rustc). CI may
regenerate and `git diff --exit-code` to catch drift.
