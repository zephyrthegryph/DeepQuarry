# dm-syntax

Source-preserving lexical and structural DM syntax layer. `lex` returns every byte of the input as an owned token, including whitespace and comments, with UTF-8 byte spans. `lex_spans` exposes the same tokens as source-backed spans for hot paths without allocating token text. The lexer recognizes multiline block strings and nested interpolation quotes as one token. `parse` groups indentation-based declarations in source order, ignores comments and multiline string contents when deciding structure, and marks every nested line in a procedure body as a statement. It preserves original headers and all tokens. `parse_expression` provides a small Pratt expression AST for early semantic prototypes, including inherited calls, `new`, membership, and assignment operators.

The parser is deliberately recovering: syntax that the prototype cannot classify remains in `ItemKind::Unknown` or receives a diagnostic. Callers must not treat a clean structural parse as evidence that all DM expressions and statements are supported. Future grammar work can enrich `Item` without changing the source and span contracts.

`parse_proc_body(&Item)` builds a statement AST from a `Proc` or `Verb` item. It handles nested `if`/`else if`/`else`, `while`, basic `for`, `return`, local `var`, assignments, calls, `break`, and `continue`. Every node retains its original header and absolute UTF-8 byte spans. Unsupported syntax becomes `StatementKind::Unsupported` with a diagnostic, so a compiler cannot quietly emit a partial body. The structural `AstFile.tokens` remains lossless and available for later grammar extensions.
