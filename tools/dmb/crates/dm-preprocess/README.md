# dm-preprocess

Ordered DME and DM include expansion with explicit source dependencies and output-line origins. `SourceProvider` abstracts source reads so the incremental compiler can route them through tracked file inputs. Include occurrences are retained even when the same file is visited twice, because macro state and declaration override order can differ.

The initial implementation supports object and function macros, named variadic macros, `##` token paste, `#X` argument stringification, `#define`, `#undef`, `#include`, `#ifdef`, `#ifndef`, integer `#if`/`#elif` expressions, `#else`/`#endif`, continued physical lines, multiline block strings, and include-cycle diagnostics. Conditional expressions support `defined`, parentheses, integer arithmetic, comparisons, shifts, and logical and bitwise operations. The output map records physical source lines, including multiline strings. Macro references inside string interpolation are expanded while literal text remains untouched. Other BYOND-specific preprocessing details still need fixtures before they can be claimed as supported. Diagnostics have typed categories; callers should reject output when errors are present.

## Incremental expansion

`PreprocessCache` retains file expansions under exact source digests and macro checkpoints. Leaf fingerprints include every identifier found in source text (including undefined names, conditions and interpolation), then follow transitive macro replacements. Unrelated macro changes reuse the expansion. Token pasting falls back to the full incoming macro environment because it can synthesize identifiers.

Nested DM includes cache their complete expansion, transitive source fingerprints, source origins, macro changes, ordered `FILE_DIR` changes, maps and skins. A subtree replay validates its source closure through `SourceProvider::fingerprint` and bypasses directive traversal and expansion. Source providers can serve fingerprints from a journal-verified retained snapshot. Missing includes, diagnostics and include-cycle contexts prevent unsafe subtree replay. DME manifests remain explicitly traversed so startup ordering and conditional asset selection retain their normal behavior.

`PreprocessedProject.unit_digests` contains exact expanded-content digests aligned with `units`. These identities are computed once on expansion and reused on cache hits, allowing downstream file outline caches to avoid hashing unchanged expanded content. Persisted unit ranges and digests are validated before reuse.

`load_incremental` reads a compact index and lazily decodes SHA-256 addressed per-file chunks. `save_incremental` writes only changed chunks and atomically publishes the index. Relative source keys permit sharing across worktrees, while every replay rechecks source and environment identity. The classic `load`/`save` API remains available for standalone callers. Expansion memory is bounded to 160 MiB, each source expansion to 512 KiB, and cache path count to 8,192; unsupported or evicted entries transparently use normal preprocessing.
