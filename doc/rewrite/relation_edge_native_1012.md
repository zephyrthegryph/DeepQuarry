# Native relation-edge requirements

This cohort converts `active_if` and `holds_while` re-evaluation from legacy endpoint change masks to actual native dependency keys. It does not rename mask constants or declare a synthetic revision field.

The user-approved endpoint query contract carries ordinary datum source and target endpoints in a dedicated typed pooled context. Pure callbacks return null to permit, or a reason to refuse. The analyzer derives their actual `(producer, key)` dependencies from the callback reads, including declared relation hops to third-party producers; content does not hand-write dependency pairs or fabricate mob actors. Publishers must be real registered tracked variables or declared native keys. Unproven dependency contracts are rejected rather than silently treated as static.

The edge owns the dependency scope. Linking binds both requirements' reads; native publication reevaluates the edge, while `active_if` refusal only disables it and `holds_while` refusal unlinks it. Binding follows actual producer lifetimes and must be removed on replacement, unlink, or endpoint deletion. Rebinding to a new target must stop observing the old target. Pure predicates never update debug counters or perform gameplay effects.

Atomic state-publication batches must expose only completed snapshots to these requirements. If one intermediate setter would refuse but the final snapshot permits, the edge must stay linked and no unlink consequences may run. An unchanged tracked setter must neither republish nor disturb the edge.

The guarded `dq_relation_edge_native_tests.dm` fixtures use distinct registered source and target keys, not old channels. They test source and target activation refusal/recovery, genuine setter no-ops, a forced drain inside an incomplete atomic batch, a real holds_while unlink, actual single-source replacement, detached-target mutation/deletion, and source/target teardown, and an actual third-party policy relation's mutation/replacement/deletion. A test-only edge subtype observes its own declared native `active` key directly: flips publish, while re-evaluation with the same result does not. The relation creates that real edge subtype through the existing `make_edge()` interface. Unlink consequence counts are updated only in the effect hook; the requirements remain pure. The suite asserts the actual edge-owned `read_scope`, its grouped native bindings and borrowed `dependency_sources`, and verifies that unlink/replacement/deletion destroys the old scope and releases its bindings. Atomic coverage updates both endpoint producers, with a forced drain between partial writes.

The existing production relation shape, conflict and endpoint-delete policies are unchanged. Broader relation membership/aggregate forwarding and scheduler mask retirement remain separate work. No old-code green run or final verification is claimed by this source note.


Delivery coalescing is **per producer/listener**, not once per edge per drain. An atomic batch changing two endpoint producers can invoke the edge scope twice, each time evaluating the same completed requirement snapshot. A setter on the tracked `active` field publishes only when its result actually flips; the second evaluation with the same result does not republish. The `multiple_producer_deliveries` test replaces the edge's real owned scope with a test-only callback-counter subtype, exercising the actual bindings and native drain. It asserts two callbacks for each two-producer batch, no transient unlink and exactly one active notification when the completed result changes. The counter belongs to the effect callback, not either pure requirement.

Movement and ancestry remain a separate dependency-contract gap. A key named `loc` has no proven native publisher in this binding contract and is rejected; declaring it would falsely claim that arbitrary movement can invalidate the requirement. Range, containment ancestry and z-level changes need real declared movement-notice dependencies with native producer lifetimes. The existing live buckling and pulling movement-notice contracts are untouched by this cohort. These endpoint-key tests do not claim generic movement or ancestry coverage.

The concrete callback is `endpoint_reason(datum/act/eval/endpoint_query/A)` on the requirement definition. `A.source` and `A.target` are generic datum endpoints. All test requirements use this typed callback and generated reads; none supplies a handwritten `read_keys()` list. The third-party policy case follows the real declared `source.policy` relation, observes its tracked readiness, and verifies retargeting and weak-producer deletion parity.

`query_fault_cleanup` directly invokes `endpoint_query()` on an unconditional-fault requirement. With normal recycling scoped through `pool_poison = FALSE`, it checks actual endpoint-context pool lease/release balances and restoration of the surrounding purity depth, then leases a fresh context to inspect reset endpoint fields and immediately releases it. It never stores or escapes the callback's pooled context, nor dereferences a remembered context after release. This verifies cleanup and guard restoration, not guard entry. This is authored regression coverage, not a claim that verification has run.
The policy predicate checks actual borrowed relation membership before reading `policy.ready`. Removing the policy clears `source.policy` through native relation lifecycle publication; the real deletion and retargeting assertions remain. An explicit raw deletion-mark query is unsupported: `gc_destroyed` has no declared ordinary tracked-field or native-key publisher. The analyzer must reject that dependency rather than invent a lifetime key. `missing_descriptor` also proves a legacy-only requirement callback cannot silently fall back to a static native query when its generated endpoint descriptor is absent.

Direct native composition coverage verifies ordered all/any refusals, not inversion, empty-any legacy parity and complete automatically generated dependency unions even when a first child would short-circuit the result. The direct leaf-query fault regression verifies context lease cleanup and restoration of the surrounding purity depth without relying on an outer edge refresh guard. It does not inspect ambient state inside the pure callback or claim to prove guard entry.


setup_fault_cleanup drives an unconditional endpoint fault through real relation linking. It checks preservation of the primary exception, removal from both endpoint records and graph queries, clearing the actual source view and detached edge fields, release of the owned read scope, and unchanged native listener counts after draining. Subsequent native endpoint publications cannot resurrect the failed setup. Its edge capture is test-only effect observation and is cleared before teardown.


Initial holds refusal preserves the public edge-shaped return while detaching it immediately. The authored regression checks inactive state, cleared endpoints and source view, empty record/graph membership and contribution cache, released scope, unchanged native listener counts, one unlink consequence and no resurrection after recovery. This fixture does not configure an aggregate, so it does not independently prove aggregate callback counts.


The active publication counter is an effect handler on the actual edge producer, not a computed cross-object observer on the source. General computed on-change getters do not currently follow dotted cross-object read dependencies reliably; that framework gap is not repaired or disguised by this cohort. Endpoint query dependency generation remains separate from that computed-getter contract.


The compatibility delivery order runs native effect hooks before legacy RX inputs. A scope input callback can therefore change the real edge active setter during RX delivery, queuing its direct native observer hook for the next native phase. The two publication-counter tests settle this boundary with exactly two drains before reading counters; they do not loop, publish manually or alter engine phases. The forced drain inside a partial atomic snapshot and the other fixture cases remain unchanged. This ordering distinguishes a queued real publication from a missing publication.

Endpoint validation also rejects `PROC_SUMMARY` on a reachable callback or helper: hand-written metadata cannot substitute for proof of the actual body. Reaching the analyzer's traversal-depth limit is an error rather than an empty dependency descriptor. Both generation and standalone semantic linting use closed virtual dispatch, so an override cannot hide an untracked input behind a typed base receiver. Targeted analyzer fixtures cover callback, method and global summaries, a deeper-than-limit helper chain, and an actual virtual override with an untracked read. These restrictions are endpoint-specific; ordinary summary and depth behavior remains unchanged.
