# Proposal: the change graph

Status: approved 2026-10-17 (decisions D1 to D7 as recommended). Branch `rewrite/change-graph`. Scope: doc section 7
(`final_api.html`, "Change tracking and dependencies"), and the engine under `code/engine/{change,stats,refs,actions,lifeforms}`.
Benchmarks are paused; every step is proven by tests only (the look pins are being deleted; no snapshots).

## 0. Summary

Today one tracked write fans out through a dozen unrelated tables, each keyed by var-name text, each with its own queue. The
design replaces that with **one graph**: every observable fact is an interned key on an entity, every consumer is a dependent with
exactly one timing class, and a write is one plan lookup plus a dispatch by class. Nothing else may register interest in a change.

1. **Keys** are ints interned at build time (runtime-only keys are interned on first use).
2. **Dependents** are anything whose result is a function of keys. Each has exactly one class: INLINE, INVALIDATE, DRAIN or OUTPUT.
3. **One write path**: `write(E, key)` finds `E.type.plan[key]` (generated by `analyze gen`), adds `E.subs[key]` when the entity has
   runtime subscribers, and dispatches by class.
4. **Hops** are generated paths. The engine keeps one subscription on the far entity's key and moves it when the relation changes.
   The backward `rel_sources` walk, the `draw_hop` special case and the `rel_watchers` special case are deleted.
5. **Scheduling** is one queue per class; an entity is in a queue at most once per frame (a per-entity frame stamp).
6. **Init** uses the same path with no init flag: drains do not open until the map settles. Creation stamps the type's default look.
7. **Safety** hooks are in `write()` and the queues once: the purity guard stays in production, everything heavier is test-only,
   production keeps a low-budget drift sweep with a metric.

## 2. Keys

A **key** names one observable fact of one entity: `(entity, key id)`.

| Kind | Examples | Publisher |
|---|---|---|
| tracked var, tracked list (version) | `charge`, `contents_list` | generated setter / list mutator |
| stat | `STAT_DENSITY` | the stat store, after a recompute that changed the value |
| relation end | `cell`, `loc` container, `rel_member` | the relation write |
| slot content | `slot:left_hand` | the slot ledger |
| capability key | `CAP_PANEL_OPEN` | `cap_set()` and the capability entry writes |
| built-in | `loc`, `dir`, `density`, `icon_state`, `invisibility` | `Move()`/`forceMove()`, `setDir()` and the setters (their choke points) |
| native band | `native("temperature")` crossing | the phase N crossing report |
| pseudo hop | `HOP_TURF`, `HOP_AREA` | `hop_moved()` |
| runtime only | an observer's custom key, a producer's `PUBLISH_CHANGE(E, key)` | the producer; interned on first use |

Interning: `analyze gen` assigns each build-time key a stable int (sorted by name, so the numbering is deterministic and diff-free)
and emits `#define KEY_<NAME>` constants (hand code never writes the int) plus a name table for logs. A runtime key is interned into
`GLOB.key_ids` (text to int) on first use and gets an id above the build range; it never needs a rebuild. Nothing at runtime uses
`vars[]`, `call()` or text keys to dispatch.

## 3. Dependents and the four classes

A **dependent** is any computation whose result is a function of keys. A dependent has exactly one class; the class says when it runs
relative to the write.

| Class | When | Dependents |
|---|---|---|
| **INLINE** | before the writer's next line | stats on the written entity and one single-valued edge away (the doc's settle rule, D4); lifeform re-keys (registry rekey, radio tune, derives, lives_while, adjacency); the derived values those need |
| **INVALIDATE** | bump a generation now, recompute lazily on read | op menus, reach caches, screentips, resolved providers |
| **DRAIN** | at the next drain point (end of trigger, start of D, P, R), coalesced per (entity, dependent) | `on_change` / `on_cross` hooks, notices, observers, pending-op requirement re-checks, sequence wakes, stats farther than one edge (the marked drains), hook attach/detach |
| **OUTPUT** | once per entity per frame, in the phase that owns the output | S: `push_to_rust`; R: `draw`, `ui_data`, hidden/granted verbs, `should_run` |

Rules:

* A new consumer picks a class. It never adds a path, a table or a queue. A consumer that cannot say which class it is has not
  declared what it needs.
* INLINE runs inside `write()` under a depth counter (the existing `stat_settle_depth`); an INLINE dependent writes only through
  `write()` so the closure is the settle rule's own: logical state settled on the written entity and one single-valued edge away.
* INVALIDATE never computes: it bumps `E.gen[class]` (or a global generation for the op engine) and the reader compares. This is
  what `op_changed()` does today as a blanket; the plan makes it per key.
* DRAIN handlers see final values (coalesced), may write (their writes plan the next pass), and are capped by `DRAIN_MAX_PASSES`.
* OUTPUT runs only outputs and must not write state (the purity guard, section 8).

The existing masks map onto it: `DEP_DRAW`, `DEP_UI`, `DEP_PUSH`, `DEP_RUN`, `DEP_VALUES`, `DEP_LEGACY` are OUTPUT slots (the
per-entity dirty mask below); `DEP_VALUES` (derive) is INLINE or DRAIN per its declaration.

## 4. The one write path

```
write(E, key)                                  // the one entry; setters, stat store, relation writes, choke points call it
    plan = E.type.plan[key]                    // one list lookup, generated; null (or the empty plan) = nothing reads it
    subs = E.subs?[key]                        // only when the entity has runtime subscribers
    if(!plan && !subs) return                  // an unread key costs the plan lookup
    for each dependent in plan.inline + subs.inline: run (settle order = rank)
    for each dependent in plan.invalidate: bump generation
    for each dependent in plan.drain + subs.drain: enqueue (entity, dependent) on the DRAIN queue, stamp-deduped
    for each output bit in plan.outputs: E.dirty |= bit; enqueue E on the OUTPUT queue once (frame stamp)
```

`E.type.plan` is a generated assoc `key id -> /datum/plan` built from the declarations by `analyze gen` (reads, stat inputs, hooks,
lifeforms, derived, draws, relation watches), sorted into the four class lists with the stat rank order precomputed. The plan is the
only place the question "who reads this key" is answered. `E.subs` is allocated only when something subscribes at runtime:
`observe()`, a pending op, a capability activation's own hooks, a `look.watch()`. A subscription is a dependent record with a class
like any other, stored per (entity, key).

D5: a type with no generated plan (a type the generator could not resolve) falls back to a plan whose OUTPUT bits are all outputs.
Each fallback is counted by `GLOB.plan_fallbacks` and a ratchet (`plan_fallback`) whose baseline shrinks to zero; when it is zero the
fallback is deleted and a missing plan is a build error.

## 5. Hops

A reactive read of a far entity's key (`holder.charge`, `loc.cell.charge`, `get_area(src).power_equip`) is a generated path of
segments from the reader to the far end. The plan of the **reader's** type holds, per path, the segment list and the dependents. At
runtime the engine keeps **one subscription per (reader, path position)**: on the far entity's `subs[key]`, pointing back at the
reader and the dependent. When a relation on the path changes, the relation write is itself a key write: its plan holds the
"re-aim" dependent (INLINE) which removes the subscription from the old far end and adds it to the new one, for the reader and for
every position downstream of that segment. A relation that the reader is not currently pointing through costs nothing.

Consequences:

* A write on the far end finds its readers by `subs[key]`, never by walking relations backward (`rel_sources`, `hop_sources`
  for non-pseudo segments, `stat_hop_index`, `draw_hop_vars`, `change_hop_keys` go).
* The pseudo hops `HOP_TURF` and `HOP_AREA` keep their publishers (`hop_moved`) but publish ordinary keys on the movers whose reads
  cross them, then the standard re-aim moves the subscription.
* Collection edges (area machines, container contents) subscribe to the collection's version key, never per member (the doc's
  "Collections" row).
* The class of a hop dependent is the class its consumer declares; a stat reached across one single-valued edge is INLINE, anything
  else on the path DRAIN (the settle rule, unchanged).
* `READS_AS(proc, key, via =)` is the same: the subscription is on the far entity's key.

## 6. Scheduling

One queue per class, an entity at most once per frame per queue:

```
/datum  var/tmp/frame_stamp[class]    // the frame number of the entity's last enqueue, per queue (a small int array or three vars)
        var/tmp/dirty_output = 0      // OUTPUT bits owed; default 0, so most entities cost one int
```

`enqueue(queue, E)`: `if(E.stamp[queue] == GLOB.frame) { E.dirty |= bits; return }` else stamp, append. Draining a queue clears the
stamp and the dirty bits as it runs the entity, so a dependent that re-marks its own entity lands in the next pass of the drain (the
pass cap) rather than spinning; a mark during an entity's own OUTPUT run is a self-mark (a test-build failure, section 8).

* This replaces the `done` list and the stale-duplicate skipping in `refresh_drain`, the `rx_pending` per-entity lists, and the
  `hook_change_pending` lists. `GLOB.stat_marked` keeps its rank order but is the DRAIN queue's `stats` lane.
* DRAIN and OUTPUT keep the kernel budgets (`KERNEL_OVER_BUDGET`, the lane budgets, `STEP_YIELD` with a saved cursor). INLINE has no
  budget (it is part of the write) and no queue.
* Drain points are unchanged: end of the current trigger, and the start of phases D, P, S and R. Phase R runs only OUTPUTs.

## 7. Init, the default look, and the blankets

**No init flag on writes.** A write during `Initialize()` takes the same path. What differs is which drain points are open:
DRAIN points do not open until the map has settled (`GLOB.map_settled`), so marks coalesce and one settling drain runs at the end.
INLINE still runs (stats are correct from the first read; the existing "initial evaluation is silent" rule is the INLINE rule with
the DRAIN deferred).

**Creation stamps the default look.** For each atom type, the look a fresh instance draws is a function of the type (its mapped
icon, state, overlays from its capabilities' static looks). It is computed once per type into a cached appearance (`type_look`), and
`New()` stamps it (one appearance assignment) and queues nothing. Types whose legacy `Initialize()` still raw-writes drawn vars would
make the stamp wrong, so they keep a **forced first draw**: a list generated from `tools/ci/init_baseline.txt` (the `Initialize`
ratchet, the types with an `init_lines` row that write a read var) that shrinks as the baseline shrinks and is deleted at zero.

**Per-type test** (landed in step 1, `dq_fresh_look_default`): a fresh instance's look equals the type's default. In step 1 the
"default" is the look the type's first fresh instance drew; the test proves a fresh look depends on the type and nothing else (the
precondition of the stamp) and lists the types it does not (the forced-draw candidates). From step 5 the same test compares the
look the stamp gave against a dry draw. The normal-tier `representative` covers a curated spread; the whole-type sweep is exhaustive.

**Round-start backlog (measured 17 October 2026, Southern Cross, `dq_draw_queue_space_requeue --full-map`).** Before step 5 every
fresh atom's first refresh was queued at creation (`caps_init()` marks `DEP_ALL`), and the drain could skip a type's later instances only
once its first instance had been refreshed and the type's verdict recorded. A map load creates everything before any drain, and a
clientless world does not advance time (`sleep_offline`), so all of it, about 310 000 space turfs among it, sat in the draw queue until
a client connected. Measured at boot: **568 934** atoms queued; **162** types still waiting for a verdict; **352 254** fresh atoms of
types whose default look is empty; **216 518** left (types that draw something, or atoms written since creation). The settle pass
costs **1.57 s** of boot. On the unit-test map: 44 394 queued, 56 types, 19 504 dropped, 213 ms.

**Re-queues after round start.** In an idle full-map world, 20 deadline passes after boot marked no space turf (the probe in
`refresh_mark()`, test builds only, counts marks of one type by caller). The paths that do mark one are writes: `update_starlight()`
(`set_glow()` through the light setters) when a neighbouring turf changes (`ChangeTurf`, `lighting_overlay.dm`), and a real write
clears the creation mark, so the stamp never hides it. `toggle_transit()` raw-writes `appearance` and marks nothing. Shuttle walls
re-queue through `breaks_light`.

**What step 5 landed (the empty-default stamp).** `code/engine/change/look_stamp.dm`. The creation mark carries `DEP_CREATED` beside
`DEP_ALL`; any real mark clears it (`refresh_mark()`). The first fresh instance a drain refreshes records the type's stamp
(`GLOB.type_look_stamp`): TRUE when the refresh left nothing (no look key, hidden or granted verbs, `cap_engine_state` watches or
flashes, derived values, side effects, periodic work; mobs never). For such a type a fresh atom is not queued at creation, the drain
drops a queued one still on its creation mark, and `refresh_settle_created()` runs after `kernel_members_ready()`: one sample per type
still pending, then the fresh atoms of stamped types leave the queue. A type whose default look is not empty keeps its first draw
(that is the forced-draw list for now: every drawing type); stamping a cached non-empty appearance was examined next and is not safe as a type-level cache: a mapped atom's var edits
(`dir`, `icon_state`, `name`, a machine's mapped flags) are instance state the draw reads, and neither the fresh-look sweep (two fresh
instances on one tile) nor the stamp can see them, so a type's cached look would be wrong for every edited instance; the saving would be
the draw() call only (the apply still runs). It becomes possible once the step 2 plan knows each draw's reads: a type whose draw reads no
var a map edit can set may share a cached look. The whole-type sweep (`dq_fresh_look_default`, sharded as a sweep pin) found 6 types
with an instance-dependent first look (the preset laptops open or closed at random; the blackbox recorder deletes a second instance;
redgates) and the runtimes fixed on this branch. The
`init_baseline.txt` filter the section above names needs the reads of each draw (an `Initialize` row is every statement, so as a list
it would force every type); it comes with the generated plans of step 2. Tests: `dq_draw_queue_default_look`,
`dq_draw_queue_space_requeue`.

**No runtime type probe.** `type_derive_flags`, `derive_probing`, `derive_side_probing` and the first-instance-always-queued rule
exist because the engine did not know what a type derives. The generated plan knows. They are deleted in step 5; D5's fallback
covers a type without a plan until the ratchet is zero.

**The blankets.** `caps_init()` marking `DEP_ALL` is replaced by the stamp plus the forced-draw list (step 5). The
`refresh_dispatched()` `DEP_ALL` after every handler, timer and periodic step is dropped when the staleness checker runs clean
without it (step 6): a handler that writes state published through the plan; one that wrote raw is a `raw_write` lint and a
staleness finding, not something to paper over.

## 8. Safety hooks

All of them hang from `write()` and the queues, once.

| Check | Production | Test builds |
|---|---|---|
| purity guard (`OP_PURE_GUARD`: no write inside a condition, requirement, output or formula) | **kept**: one global depth check in `write()` | kept |
| output-wrote-state (`derived_write_violations`) | off | on |
| self-mark (`refresh_self_marks`) | off | on (a mark of the entity whose OUTPUT is running) |
| cycle detector (stat and condition cycles, runtime link/grant cycles) | build error plus edge refusal | on |
| strict staleness (`staleness.dm`) | sampled (`STALENESS_SAMPLE`) | on |
| drift sweep (`refresh_sweep_step`) | **kept** (D6): low budget, near players, corrects and logs, emits a metric (`METRICS_EVENT`) | strict, every swept atom |
| "why did this redraw" trace (`refresh_traced`, `refresh_trace_note`) | kept | kept; the trace note moves into `enqueue()` so it sees every class |

Existing debug and AI tracing is never removed. The trace gains the key id and the dependent class per line.

## 9. Legacy adapter (D7)

The OM channels (`CHANGE_*`, `om_listen`, `changed(E, channel)`, `entity_dispatch_change`) become one **dependent** on the graph
(class DRAIN) generated from `om_listen` registrations: a write whose key maps to a channel dispatches it. It is deleted with the
last `CHANGE_*` caller; no new use may be added.

## 10. Memory

Per entity: `dirty_output` (int, default 0) and the frame stamps. `E.subs` is a lazy list, allocated when something subscribes and
dropped when empty. `rx_state` is split (step 7) into a small **presentation record** (`look_key`, `look_overlays`, `look_underlays`,
`look_filters`, `look_vis`, `look_set_bits`, `look_seen_dir`, `refresh_hidden_verbs`, `refresh_granted_verbs`, `refresh_swept`,
`worn_watched`) and a **reaction state** (ledger, listeners, observed, bands, pending, timers, at_most, containment) allocated only
by what uses it. The plan table is per type, shared, built once.

## 13. Risks and open points

* **Plan completeness is the whole game.** A dependent missing from a plan is a silent stale value; that is why the staleness
  checker and the parity test (step 2) come before any table is deleted, and why the blankets stay until step 6.
* **Order inside a class.** INLINE order is stat rank (kept). DRAIN order within a class is enqueue order, as today; a rank by the
  generated reads graph is the doc's existing "rank the build assigns" and is applied to the DRAIN lane when step 4 lands.
* **Subscription lifetime.** A hop subscription lives on the far entity; the reader's teardown must remove it (today's
  `stat_hop_teardown`, `rx_teardown` generalised). Leaks are checked by a test that counts `subs` entries after a create/destroy
  sweep.
* **Native keys** stay as they are in step 1 to 4 (bands reported in phase N publish an ordinary key).
