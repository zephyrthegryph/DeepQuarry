# Native producer keys in presentation

The integrity retirement regression exposed a missing dependency path. `get_integrity()` already declares `READS_AS(ATOM_INTEGRITY_KEY)` and the actual setter publishes that key, but draw generation retained only ordinary variable reads. Runtime draw loading also required a variable in `D.vars`. Consequently the numeric value and reactions changed while the warm sprite remained stale.

This cohort generates a separate direct-holder native draw-key table. A non-variable accessor key needs a compatible real publisher, a native type-trait publication declaration, or an existing registered logical state contract. An unrelated object's same-key publication does not establish the contract. Actual stored-variable aliases keep the existing draw-variable path. Empty child rows prevent a non-chaining override from inheriting unrelated parent dependencies.

Real native publication marks the exact presentation consumer through the existing coalesced refresh lane. It also contributes to demand detection. Logical and type-trait keys delivered through `state_changed()` use the same exact draw-key table. Presentation applying its own output suppresses its own redraw mark, matching the existing stored-variable contract; genuine reactions and stats are still notified. There is no integrity-specific redraw, new synthetic state variable, renamed channel or fake revision counter.

Native publications participate in the existing synchronous state-publication batch with distinct weak-handle/key queue rows. Their flush invokes `publish_key_changed()` rather than converting the notification into a stored-variable write. Repeated same-key publication coalesces; observers see the completed cohort even if a fixture forces an intermediate drain.

The direct-holder scope does not claim automatic cross-producer accessor binding. That requires actual membership, native key and lifetime retarget observers. Existing declared `look.watch()` and look-recipe mechanisms remain separate. Memo-output presentation integration is a dependent cohort because this branch does not yet contain the memo API.

Authored regressions cover warmed integrity draw, real damage/repair/no-op publication, a forced-drain atomic cohort, and virtual-stat draw invalidation through real source holds and release. Generator fixtures distinguish stored variables, registered logical keys, compatible publishers, unrelated publishers and native type traits. The hit snapshot producer now observes public glow values instead of raw lighting storage and excludes the internal trait override container; its helper regression uses actual glow setters. Verification results belong in the final handoff once checks complete.

Literal stat_value() reads are proven against the actual inherited STAT declaration and the declaration compiler's authoritative ID mapping, including literal source overrides. Stored stats subscribe by their variable; virtual stats subscribe by their real stat:<id> publication. Dynamic IDs, ambiguous or non-literal overrides, incompatible receivers and a virtual stat display-name alias are rejected for draw admission. Existing runtime-bound dynamic framework consumers retain their prior behavior; this does not claim general runtime-stat dependency inference.
